# 课堂需求讲解｜清洗稿

> 来源：`job-bbc4cb7bcb875dc9/transcription.txt`。本稿按议题重组，删除课堂组织、闲聊和重复口头语；不作为逐字引语依据。

## 课程任务与产品定位

各小组选择一个行业，围绕该行业设计“销冠”销售智能体。产品不是普通问答机器人：收到每一条客户消息后，都应调用大模型识别意图、提取需求，并按规则决定回复、追问、报价或升级人工。

## 建议的核心能力

1. **用户意图识别**：区分闲聊、问价、产品咨询、购买意向等情况。客户仅打招呼时不应直接推销；客户明确询价时则进入购买需求识别与信息收集。
2. **报价规则判断**：在报价前判断客户的价值点和配置偏好，避免未了解需求就报出过高或不匹配的价格。报价前的必填条件及不同条件下的策略应由业务方制定。
3. **成交价格计算**：价格与最低成交价、折扣、数量／套餐等规则必须受约束。不能让模型因客户要求“再便宜些”而突破底价；应以提示词和确定性规则共同限制。
4. **知识库问答**：回答产品优势、公司优势、服务能力等基础问题。可先使用生成的演示知识库；正式价格不应直接写死在代码中。
5. **用户意向分析**：识别高意向但尚未成交的客户，为其打标签，并据此调整跟进或推荐策略。

## 可选增强项

- **本地化资料**：将文档、PDF、Word、图片等导入并向量化，用于知识库检索。
- **转人工**：定义需要人工接管的情况与交接信息。
- **历史记录、客户数据、上下文管理**：保存客户与会话信息。
  - 短期记忆：读取最近若干轮完整对话，保证当前沟通连贯。
  - 长期记忆：将较早对话压缩为摘要或结构化客户画像，避免每次读取全量历史导致成本、时延上升。
- **语音回复／音色克隆回复**：可将模型文本接入语音服务后发送。

## 课堂强调的实现原则

- 每一条客户消息都需要进行意图识别，而不是仅在首轮判断。
- 价格规则应配置化，并与底价、折扣边界、数量／套餐条件绑定。
- 先完成基础的“识别—判断—报价—问答”闭环；本地化、人工接管、语音等能力用于完善项目，可后置。
- 需求文档应逐项写清：功能说明、拟用模型或组件、实现方案、负责人和预计工期。
