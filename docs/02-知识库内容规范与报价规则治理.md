# 装修销售 AI｜知识库内容规范与报价规则治理

## 1. 文档目的

本文定义 localhost + SQLite 本地验证版必须准备的知识、意图/价值策略、上下文记忆规则、报价样例和验收数据。

知识库承担两类职责：

1. 为 AI 提供公司、服务、材料、流程、意图策略和报价依据等可检索知识；
2. 作为报价规则样例的内容来源，经格式和冲突校验后生成 SQLite 中的版本化激活规则。

知识库检索结果本身不能直接作为价格计算结果。本地报价运行时只能使用 SQLite 中通过校验并标记为 `active` 的规则版本。

## 2. 默认装修业务边界与地区方案

### 2.1 默认业务边界

首期默认服务对象为“一家单城市经营的住宅装修公司”，业务范围如下：

| 项目 | 默认范围 |
| --- | --- |
| 客户类型 | 个人住宅业主；暂不服务企业办公、商业门店和公共工程 |
| 房屋类型 | 毛坯新房、已交付新房、旧房翻新 |
| 服务类型 | 全屋装修、局部装修、仅设计咨询、设计施工一体化 |
| 报价类型 | 基于客户自述信息的预估报价或价格区间 |
| 最终成交 | 本地 MVP 不处理成交；所有结果均为虚构/脱敏测试用预估报价 |
| 暂不支持 | 在线支付、电子合同、正式订单、施工排期、结构安全鉴定、许可审批代办 |

定制家具、软装、智能家居可以作为附加项目进入报价，但不作为首期独立主营业务。

### 2.2 默认地区规则

采用“核心服务区—灰度服务区—不承接区”三级配置：

| 地区等级 | 默认处理 |
| --- | --- |
| 核心服务区 | 可按 SQLite 激活规则生成测试用预估报价 |
| 灰度服务区 | 只返回条件性范围或停止报价，标记需要未来业务确认 |
| 不承接区 | 不生成具体报价，说明样例规则当前未覆盖 |

默认城市使用虚构配置项 `default_city`。地区无法识别、地址跨边界或规则冲突时停止具体报价并展示安全提示，不进入人工流程。

## 5. 正式报价规则的生成与运行方案

### 5.1 职责边界

- **知识库内容**：业务人员维护报价事实、适用条件、公式、解释和规则版本，是正式报价规则的内容来源。
- **规则激活流程**：把标准样例内容转换成候选规则，完成格式、范围、公式、冲突和有效期校验，再标记为本地 `active` 版本。
- **SQLite 规则库**：保存已校验、版本化的本地规则，是本地运行时报价计算的权威数据源。
- **大模型**：识别意图、提取客户参数、判断检索需求和候选方案；不自由生成 `rule_id`，也不自行决定单价、底价或最终合计。
- **知识检索**：返回带来源证据的候选 `rule_id`；候选仅用于后续 SQLite 权威规则解析。
- **报价服务**：验证规则是否有效且适用，读取对应规则版本计算明细与合计，生成可追溯报价。

### 5.2 发布流程

```text
业务人员维护知识库标准表／文档
  → 生成候选规则
  → 自动校验完整性、公式、地区、时间和冲突
  → 本地复核测试样例
  → 写入并激活 SQLite 规则版本
  → 生成知识库检索索引
  → AI 选择 rule_id 和参数
  → 服务端读取已发布版本并计算报价
```

这样可以验证“报价规则由知识内容生成”的链路，又避免把一次可能不稳定的语义检索结果直接当作计算规则。本地结果不构成正式企业报价。

### 5.3 正式规则最小字段

| 字段 | 要求 |
| --- | --- |
| `rule_id` | 永久唯一；规则修改不得复用旧版本 |
| `rule_version` | 每次发布递增并保留历史版本 |
| `status` | 草稿、已校验、激活、停用、过期 |
| `effective_from/to` | 生效／失效时间 |
| `city_scope` | 核心区、灰度区及具体行政区域 |
| `service_scope` | 全屋、局改、仅设计等适用范围 |
| `required_fields` | 计算前必须具备的客户字段 |
| `unit`、`unit_price` | 计价单位与单价；不适用时写明计算方式 |
| `formula` | 受支持的确定性公式或规则类型 |
| `minimum_price` | 最低起报价／最低成交边界 |
| `cost_floor`、`profit_floor` | 内部使用，不可向客户或模型自由暴露 |
| `includes/excludes` | 包含项与排除项 |
| `conflict_rules` | 不可叠加和优先级规则 |
| `stop_when` | 本地必须停止报价的条件 |
| `source_document/version` | 生成该规则的知识内容与版本 |
| `fixture_owner/reviewer` | 测试样例负责人和复核人 |

### 5.4 运行时校验

- `rule_id` 不存在、停用、过期、地区不符或缺少字段时，不生成具体价格。
- 模型返回的金额不作为可信输入；所有金额由报价服务重新计算。
- 每份报价保存客户参数、规则版本、计算结果、知识证据和生成时间。
- 降配／升级生成新报价版本，不覆盖历史版本。
- 同一条件命中多个互斥规则时停止报价并显示冲突错误。

## 6. 本地验证指标

| KPI | 默认目标 | 统计口径 |
| --- | --- | --- |
| 无有效规则时错误报价率 | 0% | 无有效 `rule_id` 或证据时生成具体金额的次数／相关用例数 |
| 服务端报价计算正确率 | 100% | 标准用例中明细、合计、最低价和附加费全部正确 |
| 底价／利润线违规次数 | 0 | 所有测试及线上报价中突破已发布边界的次数 |
| 规则可追溯率 | 100% | 报价中保存有效规则版本和知识来源的比例 |
| 关键报价字段提取准确率 | ≥ 90% | 标注测试集上正确提取字段数／应提取字段数 |
| 核心意图识别准确率 | ≥ 90% | 标注测试集上正确意图数／总消息数 |
| 缺失字段追问正确率 | ≥ 95% | 只追问实际缺失且当前必要字段的用例比例 |
| 上下文追忆标准用例通过率 | 100% | 指代、旧报价和事实冲突场景正确处理 |
| 长期记忆事实一致率 | 100% | 确认事实与来源消息一致 |
| 无证据价值推断率 | 0% | 意向等级和顾虑均有原文依据或标记未知 |
| 重复消息／报价数 | 0 | 双击、刷新和重试场景不重复写入 |
| 环境可复现 | 100% | 从空 SQLite 执行迁移和种子后可完成演示 |

公网可用性、真实留资、预约转化和人工处理时长不属于本地 MVP 指标。

## 7. 本地内容与规则责任

| 角色 | 责任 |
| --- | --- |
| A 集成负责人 | 维护公共契约、编排流程、规则激活入口和最终集成 |
| B AI/记忆负责人 | 维护意图、价值判断、上下文追忆和记忆策略样例 |
| C 知识/报价/SQLite负责人 | 维护知识内容模板、规则样例、SQLite 版本和报价对账 |
| D 前端/质量负责人 | 维护可见回复样例、模拟数据和端到端场景 |

任何报价样例变更必须形成新规则版本；不得直接修改正在被历史报价引用的激活版本。真实企业审批和生产发布流程留到公网阶段。
