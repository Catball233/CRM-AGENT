## 1. 规范用语与全局约定

- “必须”表示 G0 后不可由单个模块自行改变。
- HTTP 路径统一以 `/api/v1` 开头，JSON 字段统一使用 `snake_case`。
- 跨模块顶层对象必须包含 `contract_version: "1.0.0"`。
- 服务端 ID 使用 UUID；`client_message_id` 和 `retry_request_id` 由前端生成 UUID。
- 时间使用 ISO 8601 UTC，例如 `2026-08-05T08:30:00Z`。
- 金额使用非负整数“分”，币种固定为 `CNY`；不得以浮点数保存权威金额。
- 面积使用平方米，可保留两位小数；服务端必须校验有限值和合理测试范围。
- 未知字段应省略或显式使用定义允许的 `null`，不得使用空字符串代替未知。
- 客户消息默认最大 8,000 字符；数组数量必须由 Schema 设置上限。
- 客户输入、知识切片和模型输出均视为不可信数据，进入业务层前必须校验。

## 2. 核心枚举

```ts
type ConversationStage =
  | 'DISCOVERY'
  | 'QUALIFYING'
  | 'QUOTING'
  | 'NEGOTIATION'
  | 'COMPLETED'
  | 'CLOSED';

type ConversationStatus = 'ACTIVE' | 'CLOSED';
type TurnStatus = 'PROCESSING' | 'COMPLETED' | 'FAILED';

type Intent =
  | 'greeting'
  | 'consulting'
  | 'quote_request'
  | 'provide_information'
  | 'negotiation'
  | 'plan_adjustment'
  | 'rejection'
  | 'unrelated'
  | 'risk'
  | 'unclear';

type IntentLevel = 'high' | 'medium' | 'low' | 'unknown';

type NextAction =
  | 'answer_question'
  | 'ask_missing_fields'
  | 'search_knowledge'
  | 'prepare_quote'
  | 'adjust_quote'
  | 'clarify_conflict'
  | 'stop_sales_guidance'
  | 'safe_stop';

type TurnOutcome = 'answer' | 'question' | 'quote' | 'safe_stop';
```

`intent` 表示当前消息的目的，`value_assessment.level` 表示购买价值。不得再使用 `intent: "interested"` 表示价值等级。

## 3. 公共基础类型

### 3.1 来源证据

```ts
type SourceType =
  | 'message'
  | 'memory_summary'
  | 'knowledge_chunk'
  | 'quote';

interface SourceRef {
  source_type: SourceType;
  source_id: string;
  excerpt?: string;
  start_offset?: number;
  end_offset?: number;
}
```

约束：

- 价值判断证据必须至少包含一个 `source_type: "message"` 的客户原始消息引用。
- `excerpt` 只用于本地验证展示，不代替 `source_id`。
- 偏移量必须对应保存的原始文本；无法保证时不得填写。

### 3.2 需求字段

```ts
type SlotName =
  | 'city'
  | 'area_sqm'
  | 'layout'
  | 'house_state'
  | 'service_scope'
  | 'designer_tier'
  | 'material_tier'
  | 'budget_max_fen'
  | 'expected_start_date'
  | 'quantities'
  | 'special_requirements';

type SlotStatus = 'confirmed' | 'inferred' | 'conflicted';
type SlotValue = string | number | string[] | Record<string, number>;

interface SlotUpdate {
  slot: SlotName;
  value: SlotValue;
  status: SlotStatus;
  confidence?: number;
  source_refs: SourceRef[];
  conflicts_with_fact_ids?: string[];
}

interface MissingField {
  slot: SlotName;
  reason: string;
  priority: 1 | 2 | 3;
}
```

只有 `status: "confirmed"` 的必要字段可以进入报价参数。模型推断字段必须先由用户确认；冲突字段必须先澄清。

### 3.3 顾虑与客户价值

```ts
type ConcernCode =
  | 'price'
  | 'material'
  | 'design'
  | 'timeline'
  | 'quality'
  | 'after_sales'
  | 'unclear'
  | 'other';

interface Concern {
  code: ConcernCode;
  note?: string;
  evidence_refs: SourceRef[];
}

interface ValueAssessment {
  level: IntentLevel;
  evidence_refs: SourceRef[];
  reason_codes: string[];
}
```

`level: "unknown"` 可以没有证据；高、中、低必须有客户消息证据。系统不得因等级自动联系客户、提供优惠或执行外部动作。

- 摘要必须记录覆盖序号范围和来源消息。

### 7.1 报价请求

```ts
interface QuoteParameters {
  city: string;
  area_sqm: number;
  house_state: HouseState;
  service_scope: ServiceScope;
  material_tier: string;
  designer_tier?: string;
  quantities: Record<string, number>;
  special_requirements: string[];
}

type HouseState = 'rough' | 'new_finished' | 'old_renovation';
type ServiceScope = 'whole_home' | 'partial' | 'design_only';

interface QuoteRequest {
  contract_version: '1.0.0';
  conversation_id: string;
  turn_id: string;

  candidate_rule_ids: string[];
  knowledge_evidence_ids: string[];
  requested_at: string;
}
```

`QuoteRequest` 是 NestJS 内部接口，不接受浏览器直接提交。编排器只能把已确认字段和当前 turn 的知识候选放入请求。

### 7.2 报价结果

```ts
type CalculationType =
  | 'FIXED_AMOUNT'
  | 'AREA_MULTIPLY'
  | 'QUANTITY_MULTIPLY'
  | 'TIER_COEFFICIENT'
  | 'CONDITIONAL_SURCHARGE'
  | 'MINIMUM_PRICE';

interface RuleVersionRef {
  rule_id: string;
  rule_version_id: string;
  version: number;
}

interface QuoteItem {
  quote_item_id: string;
  category: 'design' | 'material' | 'construction' | 'surcharge' | 'adjustment';
  label: string;
  calculation_type: CalculationType;
  quantity?: number;
  unit?: string;
  unit_price_fen?: number;
  amount_fen: number;
  calculation_inputs: Record<string, string | number | boolean>;
  rule_ref: RuleVersionRef;
}

interface QuoteResult {
  contract_version: '1.0.0';
  quote_id: string;
  conversation_id: string;
  quote_version: number;
  parent_quote_id: string | null;
  status: 'estimated';
  currency: 'CNY';
  parameters_snapshot: QuoteParameters;
  items: QuoteItem[];
  estimated_total_fen: number;
  rule_versions: RuleVersionRef[];
  knowledge_evidence_ids: string[];
  assumptions: string[];
  exclusions: string[];
  disclaimer: string;
  created_at: string;
}

type QuoteUnavailableReason =
  | 'missing_fields'
  | 'knowledge_insufficient'
  | 'no_active_rule'
  | 'rule_not_applicable'
  | 'rule_conflict';

interface QuoteUnavailable {
  contract_version: '1.0.0';
  reason: QuoteUnavailableReason;
  missing_fields: SlotName[];
  conflicting_rule_ids: string[];
  user_safe_message: string;
}

type QuoteOutcome =
  | { kind: 'quote'; quote: QuoteResult }
  | { kind: 'unavailable'; unavailable: QuoteUnavailable };
```

报价不变量：

- `estimated_total_fen` 必须等于服务端规则计算后的明细合计及明确调整结果。
- 所有明细必须引用 SQLite 中当前计算时有效的激活规则版本。
- 重做必须生成新 `quote_id` 和递增 `quote_version`，并引用 `parent_quote_id`。
- `QuoteUnavailable` 是正常业务结果，不应伪装成 500 错误。
- 模型、知识切片、前端和用户消息中的金额都不是权威金额。
- 乘法使用十进制定点运算，每个明细按“人民币分、四舍五入 `HALF_UP`”取整，再对明细求和。
- `MINIMUM_PRICE` 通过独立调整明细补足最低价，不能静默改写其他明细金额。

## 9. HTTP API

### 9.1 创建会话

`POST /api/v1/conversations`

请求：

```json
{
  "contract_version": "1.0.0"
}
```

成功：`201 Created`，返回 `ConversationView`，初始阶段为 `DISCOVERY`、状态为 `ACTIVE`。

### 9.2 读取会话快照

`GET /api/v1/conversations/{conversation_id}`

成功：`200 OK`，返回 `ConversationSnapshot`。页面刷新只依赖该接口恢复可见状态。

### 9.3 清空本地测试会话

`DELETE /api/v1/conversations/{conversation_id}`

成功：`204 No Content`。该接口仅允许在 `local` 或 `test` 环境启用，并在 SQLite 事务中删除该会话的测试数据；生产化前必须移除或改为授权归档。

### 9.4 发送客户消息

`POST /api/v1/conversations/{conversation_id}/messages`

请求：

```json
{
  "contract_version": "1.0.0",
  "client_message_id": "f8ed9e8b-2670-494a-8fcc-f3b6f4f979c2",
  "content": "我家90平方米旧房，想做全屋中档装修，请给测试预估报价。",
  "response_mode": "complete"
}
```

`response_mode`：

- `complete`：处理完成后以 `200 OK` 返回 `ChatTurnResult`。
- `stream`：以 `200 OK` 返回 `text/event-stream`，事件定义见第 10 节。

如果请求头提供 `Idempotency-Key`，它必须等于 `client_message_id`，否则返回 `400 INVALID_REQUEST`。

重复请求仍在处理时返回 `202 Accepted` 和 `TurnAcceptedView`；已完成时直接回放 `ChatTurnResult`。

### 9.5 重试失败 turn

`POST /api/v1/conversations/{conversation_id}/turns/{turn_id}/retry`

请求：

```json
{
  "contract_version": "1.0.0",
  "retry_request_id": "dd31d7ab-7a28-4946-82c2-cad9a46c1308",
  "response_mode": "complete"
}
```

只允许重试 `FAILED` turn。系统创建新的 attempt，但不得再次保存相同客户消息。成功响应与发送消息相同。

### 9.6 本地调试快照

`GET /api/v1/debug/conversations/{conversation_id}/turns/{turn_id}`

仅在 `local/test` 环境启用，返回：

```ts
interface DebugTurnSnapshot {
  contract_version: '1.0.0';
  turn_id: string;
  analysis: AnalysisResult | null;
  context: ContextBundle;
  knowledge_evidence: KnowledgeEvidence[];
  quote_outcome: QuoteOutcome | null;
  audit_codes: string[];
}
```

禁止返回 API Key、系统提示词、供应商原始完整响应、思维链、SQLite 路径或未脱敏 PII。

### 9.7 健康检查

`GET /api/v1/health`

成功：

```json
{
  "status": "ok",
  "database": "ok",
  "contract_version": "1.0.0"
}
```

健康检查不主动调用百炼，避免把外部配额消耗当作本地进程健康条件。

## 10. SSE 事件契约

SSE 响应头至少包含：

```text
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

每个事件格式：

```text
id: evt_01
event: message.delta
data: {"contract_version":"1.0.0","event_id":"evt_01","event_type":"message.delta","sequence":2,"conversation_id":"...","turn_id":"...","emitted_at":"...","payload":{"message_id":"...","delta":"您好","index":0}}
```

```ts
type ChatEvent =
  | ChatEventBase<'turn.accepted', {
      client_message_id: string;
      replayed: boolean;
    }>
  | ChatEventBase<'analysis.completed', {
      intent: Intent;
      value_level: IntentLevel;
      next_action: NextAction;
    }>
  | ChatEventBase<'message.delta', {
      message_id: string;
      delta: string;
      index: number;
    }>
  | ChatEventBase<'question.required', {
      message: AssistantMessageView;
      question_fields: SlotName[];
    }>
  | ChatEventBase<'quote.ready', {
      message: AssistantMessageView;
      quote: QuoteResult;
    }>
  | ChatEventBase<'message.completed', {
      message: AssistantMessageView;
    }>
  | ChatEventBase<'turn.completed', {
      result: ChatTurnResult;
    }>
  | ChatEventBase<'turn.failed', {
      error: ApiErrorBody;
    }>;

interface ChatEventBase<TType extends string, TPayload> {
  contract_version: '1.0.0';
  event_id: string;
  event_type: TType;
  sequence: number;
  conversation_id: string;
  turn_id: string;
  emitted_at: string;
  payload: TPayload;
}
```

事件规则：

- 同一 turn 的 `sequence` 从 1 开始严格递增。
- 第一事件必须是 `turn.accepted`。
- 每个 turn 必须且只能出现一个终止事件：`turn.completed` 或 `turn.failed`。
- 终止事件之后不得再发送业务事件。
- `message.delta` 只用于视觉流式展示；SQLite 中的 `message.completed` 内容是恢复来源。
- SSE 断开不取消服务端处理。客户端通过会话快照恢复，或使用相同 `client_message_id` 请求回放。
- `answer/safe_stop` 顺序为可选 delta → `message.completed` → `turn.completed`。
- `question` 顺序为可选 delta → `question.required` → `turn.completed`；`quote` 顺序为可选 delta → `quote.ready` → `turn.completed`。
- 已完成 turn 的流式回放只发送 `turn.accepted(replayed=true)` 和 `turn.completed`，不重放 delta。

## 11. 幂等、并发与事务

### 11.1 重复消息规则

唯一键为 `(conversation_id, client_message_id)`，服务端同时保存内容哈希。

| 已有状态 | 相同 ID、相同内容 | 相同 ID、不同内容 |
| --- | --- | --- |
| `PROCESSING` | `202 Accepted`，返回原 `turn_id` 和 `MESSAGE_IN_PROGRESS` | `409 IDEMPOTENCY_KEY_REUSED` |
| `COMPLETED` | 返回已保存结果，`replayed: true`，不重新调用模型 | `409 IDEMPOTENCY_KEY_REUSED` |
| `FAILED` | `409 TURN_RETRY_REQUIRED`，提示调用 retry 接口 | `409 IDEMPOTENCY_KEY_REUSED` |

重试唯一键为 `(turn_id, retry_request_id)`：同一键重复提交必须回放同一 attempt；不同重试键不得让同一 turn 同时运行多个 attempt。重试时复用原客户消息、`turn_id` 和 `client_message_id`，递增 `attempt_count`。

### 11.2 同会话并发

- 一个会话同一时间最多有一个 `PROCESSING` turn。
- 使用相同消息 ID 的重复请求按上表处理。
- 使用不同消息 ID 的并发请求返回 `409 CONVERSATION_BUSY`，不得排队或并行写记忆。

### 11.3 事务边界

1. 接收事务：保存客户消息、turn 和幂等记录，状态设为 `PROCESSING`。
2. 外部模型与知识调用：不得保持 SQLite 写事务。
3. 完成事务：原子保存分析、事实变化、证据、报价/明细、助手消息、阶段和 `COMPLETED` 状态。
4. 失败事务：保存脱敏错误与 `FAILED` 状态，不提交部分报价。
5. 应用启动时：遗留 `PROCESSING` turn 标记为 `FAILED`，错误码为 `INTERRUPTED_BY_RESTART`，允许显式重试。

## 12. 错误契约

```ts
interface ApiErrorBody {
  code: string;
  message: string;
  retryable: boolean;
  request_id: string;
  details?: Record<string, unknown>;
}

interface ApiError {
  contract_version: '1.0.0';
  error: ApiErrorBody;
}
```

| HTTP | 错误码 | `retryable` | 说明 |
| --- | --- | --- | --- |
| 400 | `INVALID_REQUEST` | false | JSON、Schema、版本或参数不合法 |
| 404 | `CONVERSATION_NOT_FOUND` | false | 会话不存在 |
| 404 | `TURN_NOT_FOUND` | false | turn 不存在 |
| 409 | `CONVERSATION_BUSY` | true | 同会话已有不同消息处理中 |
| 409 | `IDEMPOTENCY_KEY_REUSED` | false | 同一消息 ID 对应不同内容 |
| 409 | `TURN_RETRY_REQUIRED` | true | 失败 turn 必须使用重试接口 |
| 409 | `TURN_NOT_RETRYABLE` | false | 非失败 turn 被请求重试 |
| 422 | `AI_OUTPUT_INVALID` | true | 模型输出两次校验后仍失败 |
| 503 | `MODEL_UNAVAILABLE` | true | 百炼模型暂不可用 |
| 503 | `KNOWLEDGE_UNAVAILABLE` | true | 百炼知识服务暂不可用 |
| 500 | `PERSISTENCE_ERROR` | true | SQLite 事务失败 |
| 500 | `INTERNAL_ERROR` | false | 未分类内部错误 |

规则不足、字段不足、知识不足和报价规则冲突优先作为 `QuoteUnavailable` 进入安全回复。只有整轮无法产生安全结果时才返回 HTTP/SSE 错误。

错误 `message` 必须是可展示的安全文案；`details` 不得包含堆栈、SQL、密钥、提示词或供应商原始响应。

## 14. 规则导入与激活边界

`RuleImportBundle` 至少包含：

- `bundle_id`、`source_document`、`source_version`；
- 一组带 `rule_id`、版本、地区、适用条件、计算类型、整数金额/系数、有效期和冲突组的规则；
- fixture 负责人、复核人和人工对账结果。

```ts
interface RuleDefinition {
  rule_id: string;
  version: number;
  city: string;
  calculation_type: CalculationType;
  amount_fen?: number;
  unit_price_fen?: number;
  coefficient?: number;
  base_rule_id?: string;
  minimum_price_fen?: number;
  conditions: Record<string, string | number | boolean>;
  conflict_group?: string;
  effective_from: string;
  effective_to?: string;
}

interface RuleImportBundle {
  contract_version: '1.0.0';
  bundle_id: string;
  source_document: string;
  source_version: string;
  rules: RuleDefinition[];
  fixture_owner: string;
  fixture_reviewer: string;
  reconciliation_fixture_ids: string[];
}

interface RuleValidationIssue {
  rule_id?: string;
  code: string;
  message: string;
  severity: 'error' | 'warning';
}

interface RuleValidationResult {
  valid: boolean;
  issues: RuleValidationIssue[];
}

interface RuleImportResult {
  bundle_id: string;
  candidate_rule_version_ids: string[];
}

interface RuleActivationResult {
  activated_rule_version_ids: string[];
  rejected_rule_version_ids: string[];
  issues: RuleValidationIssue[];
}
```

计算类型的必需输入：

| 类型 | 必需规则字段 | 计算语义 |
| --- | --- | --- |
| `FIXED_AMOUNT` | `amount_fen` | 固定金额 |
| `AREA_MULTIPLY` | `unit_price_fen` + 已确认 `area_sqm` | 面积 × 每平方米单价 |
| `QUANTITY_MULTIPLY` | `unit_price_fen` + 已确认数量 | 数量 × 单价 |
| `TIER_COEFFICIENT` | `base_rule_id` + `coefficient` | 已解析基础金额 × 档位系数 |
| `CONDITIONAL_SURCHARGE` | `amount_fen` + `conditions` | 条件命中后增加固定附加费 |
| `MINIMUM_PRICE` | `minimum_price_fen` | 合计不足最低价时生成补差明细 |

规则缺少对应必需字段、引用自身/循环引用、系数非正数或条件无法解析时，校验必须失败。
`quantities` 的键必须来自规则白名单参数，值必须为已确认、有限且非负的数值。

约束：

- `validate` 不写激活规则。
- `import_candidate` 只创建候选版本，不覆盖历史版本。
- `activate` 必须在事务内检查版本、有效期、冲突和公式白名单。
- AI、知识 Provider 和浏览器均不得调用 `activate`。
- P0 可由本地 CLI 调用 `RuleImportService`，不要求管理后台和公网管理接口。

## 15. 安全与数据隔离

- API Key 只由 NestJS 进程读取，不进入 HTTP、SSE、SQLite、调试快照或日志。
- Next.js 不直接连接 SQLite，也不直接调用百炼。
- 发送给百炼的数据只包含当前消息和已构建的必要上下文；不得发送数据库文件、本地路径或环境变量。
- 知识内容只能作为不可信证据，不能授予工具调用、规则激活或写库权限。
- 所有会话数据查询必须包含 `conversation_id`；引用其他会话 ID 时返回空结果并记录契约违规。
- 测试输入发现疑似真实手机号或身份信息时设置 `pii` 标志，不进入长期记忆。
- 日志默认记录 ID、耗时、状态和脱敏错误码，不记录完整客户消息和知识切片。

## 16. 状态机约束

| 当前阶段 | 允许进入 | 说明 |
| --- | --- | --- |
| `DISCOVERY` | `DISCOVERY`、`QUALIFYING`、`CLOSED` | 问候、咨询、开始收集或拒绝 |
| `QUALIFYING` | `QUALIFYING`、`QUOTING`、`CLOSED` | 缺失字段、冲突澄清或满足报价 |
| `QUOTING` | `NEGOTIATION`、`COMPLETED`、`QUALIFYING`、`CLOSED` | 报价、报价不可用返回补充信息或结束 |
| `NEGOTIATION` | `NEGOTIATION`、`QUOTING`、`COMPLETED`、`CLOSED` | 降配、升级或接受测试方案 |
| `COMPLETED` | `DISCOVERY`、`NEGOTIATION`、`CLOSED` | 用户继续新问题或调整旧报价 |
| `CLOSED` | 无 | 终止会话；继续测试须创建新会话 |

AI 只给出阶段建议。编排器必须拒绝非法跳转并记录 `INVALID_STAGE_TRANSITION` 审计事件。

## 17. 12 个验收场景的契约映射

| 场景 | 主要契约 | 必须验证 |
| --- | --- | --- |
| S01 普通咨询 | `AnalysisResult`、`KnowledgeSearchResult`、`ChatTurnResult` | `outcome=answer`，不生成报价 |
| S02 缺失字段 | `SlotUpdate[]`、`MissingField[]` | `outcome=question`，最多追问 3 项 |
| S03 价值判断 | `ValueAssessment`、`Concern[]` | 等级有客户消息证据 |
| S04 上下文追忆 | `ContextBundle.recalled_items` | 只召回当前会话正确报价 |
| S05 长对话记忆 | `CustomerFact`、`MemorySummaryView` | 确认、推断和冲突不混用 |
| S06 有效报价 | `QuoteRequest`、`QuoteResult` | 激活规则、整数金额和证据可追溯 |
| S07 报价重做 | `parent_quote_id`、`quote_version` | 新版本不覆盖历史 |
| S08 无效/冲突规则 | `QuoteUnavailable` | 不生成具体金额 |
| S09 无关/拒绝 | `Intent`、状态机 | 不进入报价和强销售链路 |
| S10 提示词注入 | `SafetyFlag`、安全错误 | 不泄露密钥、提示词或路径 |
| S11 未授权外部动作 | `SafetyFlag.external_action` | 不保存真实 PII、不伪造发送 |
| S12 重复与重启 | turn 状态、幂等表、retry API | 无重复消息/报价/记忆事件 |

## 18. Schema、fixture 与兼容规则

建议定义位置：

```text
packages/contracts/
├── public/       # HTTP、SSE、前端可见类型
├── internal/     # AI、知识、记忆、报价、规则和Repository类型
├── errors/       # ApiError和错误码
└── index.ts

packages/test-fixtures/
├── contracts/
├── scenarios/
├── knowledge/
└── quote-rules/
```

规则：

- TypeScript 类型必须由运行时 Schema 推导，禁止手写两套不同定义。
- HTTP、SSE、Provider 和 Repository 边界都执行运行时校验。
- 每个顶层 Schema 至少提供一个有效样例和一个失败样例。
- 新增可选字段或枚举兼容值升次版本；删除、改名、改变语义或必填性升主版本。
- 修改公共契约由 A 发起，受影响的 B/C/D 至少一人批准；报价或记忆语义变更必须对应负责人批准。
- 冻结后禁止各模块复制 DTO；只从 `packages/contracts` 引用。
