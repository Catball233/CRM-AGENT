# 接口契约 v1.1｜采购、促销与利润底线设计提案

> 状态：**Draft／待 A、B、C、D 评审，未批准实施**  
> 关联：Issue #20（C-06）  
> 目标版本：`1.1.0`  
> 基线：`1.0.0`  
> 修订：Draft 5（2026-08-06，B 已批准；已落实 A 的公共传输契约意见和 D 的客户分类／销售编排隔离要求，等待 C／D 复审与 A 终审）  
> 本文只定义设计边界和测试契约，不修改冻结的 v1.0 Runtime Schema、SQLite 迁移或生产规则。

## 1. 目标与非目标

### 1.1 目标

在保持 v1.0 请求和响应可继续解析的前提下，为以下能力定义可评审的 v1.1 契约：

- 家具、家电、软装代采需求与客户可见报价；
- 供应商批发报价快照、配送、安装、税费和质保成本；
- 现金优惠、赠品和免费服务；
- 最低利润率、最大优惠率和不可亏损底线；
- 高／中／低意向对应的规则化候选方案；
- 供应商报价过期、促销不适用和利润底线突破时的安全停止；
- 公共对象与仅服务端内部对象的强隔离。

### 1.2 非目标

- 不连接真实供应商系统，不存放真实企业采购价格；
- 不实现支付、合同、订单、库存或物流履约；
- 不允许模型、前端或用户直接决定优惠金额；
- 不改变 v1.0 字段含义，不向 v1.0 strict Schema 直接追加字段；
- 不在本文中修改 `packages/contracts`、SQLite 表或激活规则。

## 2. 必须批准的核心决策

1. **双版本并存**：保留现有 v1.0 Schema 和导出不变，新增独立 v1.1 Schema；不得把 `ContractVersionSchema` 从字面量直接改为联合类型后让旧 Schema 接收新载荷。
2. **会话锁定版本**：创建会话时选择 `1.0.0` 或 `1.1.0`，该会话后续 HTTP、SSE、报价和快照必须使用同一版本，不允许同一会话中途切换。
3. **价格权威唯一**：知识检索只返回证据和候选规则 ID；最终价格、优惠及利润校验只读取 SQLite 中已激活且在计算时有效的规则版本。
4. **内部数据隔离**：供应商报价、内部成本、利润率、最低成交金额和最大优惠能力仅存在于服务端对象及受控存储中，禁止进入 HTTP、SSE、`QuoteResult`、`ChatEvent` 或客户日志。
5. **优惠不是负明细**：`QuoteItem.amount_fen` 保持非负；现金优惠通过 `discount_total_fen` 和 `applied_promotions` 表达。
6. **历史不可覆盖**：供应商快照、规则版本和报价版本只新增，不覆盖已被报价引用的历史记录。
7. **客户分类与销售编排仅内部可见**：`intent`、`value_level`、`recommended_next_action` 和内部 `ConversationStage` 只用于服务端分析、编排与受控审计，不进入公共 HTTP／SSE、页面状态、浏览器存储、埋点或普通／错误日志。

## 3. v1.0／v1.1 版本协商

### 3.1 Schema 组织建议

实施获批后建议采用并列模块，而不是改写 v1.0：

```text
packages/contracts/src/v1/      # 现有 1.0.0 Schema，保持行为不变
packages/contracts/src/v1_1/    # 新增 1.1.0 Schema
packages/contracts/src/versioned.ts
```

`versioned.ts` 只在传输适配层按顶层 `contract_version` 分派到对应 Schema。业务模块必须显式声明处理的版本，禁止在解析前先丢弃未知字段。

### 3.2 协商规则

- `POST /api/v1/conversations` 的 `contract_version` 决定新会话版本；服务端只接受明确支持的字面量。
- 会话版本持久化后不可修改；后续请求版本与会话不一致时返回 `400 INVALID_REQUEST`，不得静默升级或降级。
- v1.0 请求始终由原 v1.0 strict Schema 解析，响应仍为 v1.0，不出现任何 v1.1 字段。
- v1.1 请求由独立 v1.1 strict Schema 解析，HTTP 和 SSE 响应统一返回 `contract_version: "1.1.0"`。
- v1.1 报价不得自动降级为 v1.0，因为促销总额、代采项目和报价有效期无法无损表示。
- 不支持的版本返回安全错误；错误详情只列出可支持版本，不回显原始未可信载荷。

### 3.3 兼容性承诺

| 场景 | 预期结果 |
| --- | --- |
| 既有 v1.0 fixture | 继续由原 Schema 解析并通过 |
| v1.0 载荷携带 v1.1 字段 | 因 strict Schema 拒绝 |
| v1.1 载荷缺少新增必填字段 | 由 v1.1 Schema 拒绝 |
| v1.1 请求访问 v1.0 会话 | `400 INVALID_REQUEST` |
| 未知版本 | 安全拒绝，不创建会话或半成品数据 |

## 4. v1.1 公共传输与模块间边界草案

以下类型均为提案；字段名最终由 A 批准后才可进入 Runtime Schema。除 4.2 明确标记的服务端模块间对象外，本节其他对象均为客户可见公共投影；公共 HTTP／SSE 只能引用这些明确列出的公共对象，不能引用或展开 4.2 的服务端对象。

### 4.1 代采需求

```ts
type ProcurementCategory = 'furniture' | 'appliance' | 'soft_furnishing';

interface ProcurementRequirementItemV1_1 {
  request_item_id: string;           // UUID，仅标识本次客户需求
  category: ProcurementCategory;
  catalog_item_id?: string;          // 可公开的公司目录 ID，不是供应商 SKU
  label: string;
  quantity: number;                  // 正数，按品类规则限制上限
  delivery_required: boolean;
  installation_required: boolean;
  warranty_required: boolean;
  notes: string[];
}

interface ProcurementRequirementsV1_1 {
  requested: boolean;
  delivery_region?: string;
  items: ProcurementRequirementItemV1_1[];
}
```

约束：

- `requested: false` 时 `items` 必须为空；
- 任一项目需要配送时 `delivery_region` 必填，否则允许省略；
- 报价所用项目必须来自客户已确认事实，不得根据模型推断直接采购；
- 客户对象不得出现供应商 ID、供应商 SKU、批发价、内部成本或内部质保成本。

### 4.2 B 模块仅服务端可输出的商业意图信号

本小节定义 B 到服务端编排器／C 的模块间对象，不属于客户可见投影，不得导出到浏览器包或进入 HTTP／SSE、页面状态、浏览器存储、埋点及普通日志。

```ts
interface ProcurementCategorySignalV1_1 {
  category: ProcurementCategory;
  evidence_refs: SourceRef[];
}

interface BenefitPreferenceSignalV1_1 {
  benefit: 'cash_discount' | 'gift' | 'free_service';
  evidence_refs: SourceRef[];
}

interface CommercialIntentSignalsV1_1 {
  procurement: {
    interest: 'requested' | 'declined' | 'unknown';
    evidence_refs: SourceRef[];
    categories: ProcurementCategorySignalV1_1[];
  };
  promotion: {
    interest: 'requested' | 'declined' | 'unknown';
    evidence_refs: SourceRef[];
    preferred_benefits: BenefitPreferenceSignalV1_1[];
  };
}
```

证据不变量：

- `interest` 不是 `unknown` 时，该信号的 `evidence_refs` 至少包含一个 `source_type: "message"` 的客户原始消息引用；
- 每个采购品类和权益偏好都有自己的客户消息证据，不能只依赖对象级总证据；
- `declined` 和 `unknown` 时对应品类／偏好数组必须为空；`unknown` 与“明确拒绝”不得共用空数组语义；
- `value_assessment` 仍由既有 `AnalysisResult` 独立承载，禁止从 `value_level` 自动推导 `promotion.interest` 或 `preferred_benefits`；
- 客户原话中的金额可以作为受长度限制的 `SourceRef.excerpt` 保留，但不得转换成 B 决定或批准的优惠金额。

B 只负责识别意图、偏好和证据，不得输出：

- 折扣金额、折扣基点、最低成交价或利润率；
- 供应商、成本或批发报价；
- 可直接激活的规则定义；
- 无知识证据支持的 `rule_id`。

`recommended_next_action` 继续位于 `AnalysisResultV1_1.recommended_next_action`，不重复放入 `CommercialIntentSignalsV1_1`。采购／促销信息不全时使用 `ask_missing_fields`，需要报价或调整时只建议 `prepare_quote`／`adjust_quote`；该字段是编排建议，不是报价或促销授权。

### 4.3 报价参数

```ts
type PublicQuantityUnitV1_1 = 'count' | 'sqm' | 'linear_m';

interface PublicQuantityItemV1_1 {
  public_quantity_id: string;        // UUID，仅引用已批准的公开数量目录项
  unit: PublicQuantityUnitV1_1;
  value: number;                     // 有限正数，范围由公开目录项约束
}

interface QuoteParametersV1_1 {
  city: string;
  area_sqm: number;
  house_state: HouseState;
  service_scope: ServiceScope;
  material_tier: string;
  designer_tier?: string;
  quantities: PublicQuantityItemV1_1[];
  special_requirements: string[];
  procurement: ProcurementRequirementsV1_1;
}
```

`PublicQuantityItemV1_1` 必须使用 strict Schema；公开契约中不得使用自由 `Record` 承载数量。`public_quantity_id` 只能引用版本化、已批准的公开数量目录，不得接受任意业务键名；服务端必须校验 ID 存在、目录状态有效、`unit` 与目录定义一致，并拒绝重复 ID。没有数量时发送空数组，不以自定义键表达缺失值。

数量项只允许 `public_quantity_id`、`unit` 和 `value` 三个字段。出现未知键，或混入 `rule_id`、规则版本、供应商引用、成本、利润、底价、内部计算参数及其同义字段时，Runtime Schema 必须立即拒绝，不能依靠删除未知字段后继续报价。

`QuoteRequestV1_1` 仍为 NestJS 内部接口。它可以携带已确认参数、知识证据 ID、候选报价规则 ID、候选促销规则 ID和意向等级，但不得接受浏览器直接提交，也不得包含自定义折扣金额。

候选规则 ID 只能来自知识检索或编排器的非权威提示。C 必须按 `requested_at` 重新查询 SQLite，验证规则处于 `active`、版本和适用条件一致后才能计算；上游候选中携带或暗示的金额一律忽略。客户指定优惠金额、询问最大优惠或索取成本／底价时，B 只保留意图与原文证据，由 C 根据激活规则判断是否存在可用方案。

### 4.4 客户可见促销

```ts
type PublicPromotionType = 'cash_discount' | 'gift' | 'free_service';

interface AppliedPromotionV1_1 {
  promotion_id: string;              // 本次应用记录的 UUID
  promotion_type: PublicPromotionType;
  label: string;
  discount_fen: number;              // 现金优惠为正数；赠品／免费服务固定为 0
  benefit_quote_item_ids: string[];  // 赠品／免费服务对应的 0 元客户明细
}
```

约束：

- 现金优惠：`discount_fen > 0` 且 `benefit_quote_item_ids` 为空；
- 赠品／免费服务：`discount_fen = 0` 且至少引用一个客户可见的 0 元明细；
- 客户可见的“价值”只能使用批准的公开目录价，不得使用内部成本冒充；
- 客户不能通过请求体传入 `discount_fen`。

### 4.5 客户可见报价

v1.1 必须定义独立 `QuoteItemV1_1` 和 `QuoteResultV1_1`，不得直接放宽 v1.0 Schema。客户可见计算依据采用封闭的判别联合，禁止开放 `Record<string, ...>`：

```ts
interface QuoteItemBaseV1_1 {
  quote_item_id: string;
  category:
    | 'design'
    | 'material'
    | 'construction'
    | 'surcharge'
    | 'adjustment'
    | 'procurement'
    | 'promotion_benefit';
  procurement_category?: ProcurementCategory;
  label: string;
  amount_fen: number;                // 始终为非负整数分
}

type QuoteItemV1_1 = QuoteItemBaseV1_1 & (
  | {
      calculation_type: 'FIXED_AMOUNT';
      pricing_basis: { kind: 'fixed' };
    }
  | {
      calculation_type: 'AREA_MULTIPLY';
      pricing_basis: { kind: 'area'; area_sqm: number; unit_price_fen: number };
    }
  | {
      calculation_type: 'QUANTITY_MULTIPLY';
      pricing_basis: {
        kind: 'quantity';
        quantity: number;
        unit: string;
        unit_price_fen: number;
      };
    }
  | {
      calculation_type: 'TIER_COEFFICIENT';
      pricing_basis: { kind: 'tier'; public_tier_code: string };
    }
  | {
      calculation_type: 'CONDITIONAL_SURCHARGE';
      pricing_basis: { kind: 'condition'; public_condition_code: string };
    }
  | {
      calculation_type: 'MINIMUM_PRICE';
      pricing_basis: { kind: 'minimum_adjustment' };
    }
);

interface QuoteResultV1_1 {
  contract_version: '1.1.0';
  quote_id: string;
  conversation_id: string;
  quote_version: number;
  parent_quote_id: string | null;
  status: 'estimated';
  currency: 'CNY';
  parameters_snapshot: QuoteParametersV1_1;
  items: QuoteItemV1_1[];
  subtotal_fen: number;
  discount_total_fen: number;
  applied_promotions: AppliedPromotionV1_1[];
  estimated_total_fen: number;
  assumptions: string[];
  exclusions: string[];
  disclaimer: string;
  valid_until: string;
  created_at: string;
}
```

Runtime Schema 实现时，`QuoteItemBaseV1_1` 和联合中的每个分支都必须使用 strict 校验；`calculation_type` 与 `pricing_basis.kind` 不匹配、携带其他计算类型字段或出现未知键时一律拒绝。

所有公开 `*_id` 均使用 UUID。`created_at`、`valid_until`、`completed_at` 和 `emitted_at` 等公开时间字段均使用带时区偏移的 ISO 8601（与现有 `IsoDateTimeSchema = z.string().datetime({ offset: true })` 一致）；允许 `Z` 或显式偏移，例如 `2026-08-06T10:00:00Z`、`2026-08-06T18:00:00+08:00`，不接受缺少偏移的本地时间。

公共不变量：

```text
subtotal_fen = sum(items[].amount_fen)
discount_total_fen = sum(applied_promotions[].discount_fen)
0 <= discount_total_fen <= subtotal_fen
estimated_total_fen = subtotal_fen - discount_total_fen
created_at < valid_until
```

`QuoteResultV1_1`、`ChatEventV1_1`、HTTP／SSE 和页面状态中禁止出现以下字段或同义字段：

```text
total_cost_fen
minimum_margin_bps
maximum_discount_bps
floor_revenue_fen
margin_headroom_fen
supplier_id / supplier_name / supplier_sku
wholesale_cost_fen
delivery_cost_fen / installation_cost_fen / warranty_cost_fen / tax_cost_fen
```

`rule_ref`、`rule_versions`、`knowledge_evidence_ids` 和供应商快照引用全部保留在服务端内部追溯账本，不进入客户响应。客户咨询时仅使用已有的 `quote_id` 作为公开不透明查询标识；服务端通过内部映射追溯规则和证据。

### 4.6 不可报价结果

服务端内部原因在保留 v1.0 原因的基础上新增：

- `supplier_quote_expired`：所需代采项目没有计算时有效的供应商快照；
- `promotion_not_applicable`：当前请求明确要求应用某候选促销，但没有可合法应用的激活规则；
- `margin_floor_exceeded`：请求的调整会使最终收入低于成本／最低利润底线。

这些原因只属于 `InternalQuoteUnavailableReasonV1_1`，不得直接传给客户端。公共 `QuoteUnavailableV1_1.reason` 只允许：

```ts
type PublicQuoteUnavailableReasonV1_1 =
  | 'missing_fields'
  | 'knowledge_insufficient'
  | 'quote_temporarily_unavailable'
  | 'adjustment_unavailable';

type PublicQuoteMissingFieldV1_1 =
  | 'city'
  | 'area_sqm'
  | 'layout'
  | 'house_state'
  | 'service_scope'
  | 'material_tier'
  | 'designer_tier'
  | 'budget_max_fen'
  | 'expected_start_date'
  | 'quantities'
  | 'special_requirements'
  | 'procurement'
  | 'delivery_region'
  | 'procurement_items';

type PublicRetryTriggerV1_1 =
  | 'customer_input'
  | 'service_refresh'
  | 'plan_change'
  | 'none';

interface PublicRetryV1_1 {
  allowed: boolean;
  trigger: PublicRetryTriggerV1_1;
  retry_after_seconds?: number; // 仅 service_refresh；1..3600 的整数
}

interface QuoteUnavailableV1_1 {
  contract_version: '1.1.0';
  conversation_id: string;             // UUID
  turn_id: string;                     // UUID
  reason: PublicQuoteUnavailableReasonV1_1;
  missing_fields: PublicQuoteMissingFieldV1_1[];
  user_safe_message: string;           // 仅来自批准的公开话术模板
  retry: PublicRetryV1_1;
}

type QuoteOutcomeV1_1 =
  | { kind: 'quote'; quote: QuoteResultV1_1 }
  | { kind: 'unavailable'; unavailable: QuoteUnavailableV1_1 };
```

`QuoteUnavailableV1_1`、`PublicRetryV1_1` 和 `QuoteOutcomeV1_1` 的所有对象与联合分支均为 strict。业务不变量如下：

- `reason: missing_fields` 时 `missing_fields` 必须为非空去重数组，`retry` 必须为 `{ allowed: true, trigger: "customer_input" }`；
- 其他原因的 `missing_fields` 必须为空；`knowledge_insufficient` 可在补充客户资料时使用 `customer_input`，也可在规则／知识恢复后使用 `service_refresh`；
- `quote_temporarily_unavailable` 只允许 `service_refresh`；`adjustment_unavailable` 只允许 `plan_change` 或 `none`；
- `allowed: false` 当且仅当 `trigger: none`；`retry_after_seconds` 只允许在 `allowed: true` 且 `trigger: service_refresh` 时出现，并为 `1..3600` 的整数；
- 不可报价是正常业务结果，完整响应返回 `QuoteOutcomeV1_1.kind: "unavailable"`，不能伪装成 HTTP 500；只有请求格式、鉴权、并发、持久化或服务异常才使用 HTTP 错误信封。

字段范围固定为：`missing_fields` 最多 20 项，`user_safe_message` 长度 `1..1000`；超过上限、重复项、空文本、非 UUID 标识或未知键一律拒绝，不做静默截断或删除。

| 内部原因 | 客户公开原因 |
| --- | --- |
| `missing_fields` | `missing_fields` |
| `knowledge_insufficient` | `knowledge_insufficient` |
| `supplier_quote_expired`、`no_active_rule`、`rule_not_applicable`、`rule_conflict` | `quote_temporarily_unavailable` |
| `promotion_not_applicable`、`margin_floor_exceeded` | `adjustment_unavailable` |

对外提示只说明“暂时无法生成可靠报价”或“当前调整无法应用”，不得输出具体成本、底线、差额、规则冲突或供应商身份。若基础报价仍可独立生成，促销不适用应返回不含该促销的新报价；只有当前操作必须依赖该促销时才返回不可用结果。

### 4.7 HTTP／SSE 与 `ChatEventV1_1` 公共传输契约

v1.1 不复用含 `cited_evidence_ids` 的 v1.0 `AssistantMessageViewSchema`，而是定义不携带内部证据引用的公共消息投影：

```ts
interface PublicUserMessageV1_1 {
  message_id: string;                 // UUID
  role: 'user';
  content: string;
  sequence: number;                   // 正整数
  created_at: string;                 // 带偏移 ISO 8601
}

interface PublicAssistantMessageV1_1 {
  message_id: string;                 // UUID
  role: 'assistant';
  content: string;
  sequence: number;                   // 正整数
  created_at: string;                 // 带偏移 ISO 8601
}

type PublicTurnOutcomeV1_1 =
  | 'answer'
```

SSE 使用以下封闭判别联合；事件顶层和每个 `payload` 均为 strict，不允许透传任意对象：

```ts
interface ChatEventBaseV1_1 {
  contract_version: '1.1.0';
  event_id: string;                   // UUID
  sequence: number;                   // 同一 turn 内严格递增的正整数
  conversation_id: string;            // UUID
  turn_id: string;                    // UUID
  emitted_at: string;                 // 带偏移 ISO 8601
}

type ChatEventV1_1 =
  | (ChatEventBaseV1_1 & {
      event_type: 'turn.accepted';
      payload: { client_message_id: string; replayed: boolean };
    })
  | (ChatEventBaseV1_1 & {
      event_type: 'message.delta';
      payload: { message_id: string; delta: string; index: number };
    })
  | (ChatEventBaseV1_1 & {
      event_type: 'question.required';
      payload: {
        message: PublicAssistantMessageV1_1;
        question_fields: PublicQuoteMissingFieldV1_1[];
      };
    })
  | (ChatEventBaseV1_1 & {
      event_type: 'quote.ready';
      payload: { message: PublicAssistantMessageV1_1; quote: QuoteResultV1_1 };
    })
  | (ChatEventBaseV1_1 & {
      event_type: 'quote.unavailable';
      payload: {
        message: PublicAssistantMessageV1_1;
        unavailable: QuoteUnavailableV1_1;
      };
    })
  | (ChatEventBaseV1_1 & {
      event_type: 'message.completed';
      payload: { message: PublicAssistantMessageV1_1 };
    })
  | (ChatEventBaseV1_1 & {
      event_type: 'turn.completed';
      payload: { result: ChatTurnResultV1_1 };

  | (ChatEventBaseV1_1 & {
      event_type: 'turn.failed';

```

v1.1 公共事件不定义 `analysis.completed`，也不发送 `intent`、`value_level`、`next_action`、`recommended_next_action` 或内部销售阶段。需要进度反馈时，客户端只使用 `turn.accepted` 表示处理中，并通过 `message.delta`／`question.required`／`quote.ready`／`quote.unavailable` 等实际客户结果事件更新页面；不得把内部分析步骤改名为“进度”后透传。`message.delta.index` 为从 0 开始、同一消息严格连续递增的整数。

同一 turn 内事件 `sequence` 必须从 1 开始严格递增；`message.delta.delta` 长度为 `1..8000`。`question.required.question_fields` 必须为 `1..3` 个去重值；事件中的嵌套 `conversation_id`、`turn_id`、消息 ID 和最终结果必须与事件链上下文一致。上述跨事件条件由流消费者状态机校验，单事件字段范围由 Runtime Schema 校验。

HTTP 和 SSE 的错误必须使用同一严格公共错误体：

```ts
type PublicApiErrorCodeV1_1 =
  | 'INVALID_REQUEST'

```

`PublicApiErrorV1_1` 和 `PublicApiErrorBodyV1_1` 均为 strict；v1.0 可保留既有 `details` 行为，但 v1.1 公共错误不提供开放 `details` 字段。HTTP 完整模式成功响应必须严格解析为 `ChatTurnResultV1_1`，失败响应严格解析为 `PublicApiErrorV1_1`。SSE 每条 `data` 必须严格解析为一个 `ChatEventV1_1`，SSE `event` 值必须等于 `event_type`，SSE `id` 必须等于 `event_id`；流建立后的失败只允许发送 `turn.failed`，随后关闭流，不得发送未列入联合的临时事件。

`PublicApiErrorBodyV1_1.retry_after_seconds` 只允许在 `retryable: true` 时出现；`retryable: false` 时必须省略。错误 `message` 不得直接使用异常文本、模型输出、数据库错误、知识切片或第三方响应正文，只能由错误码映射到批准的公开模板。

以下字段及其 snake_case、camelCase、缩写或业务同义词，在 `QuoteUnavailableV1_1`、`ChatTurnResultV1_1`、全部事件 payload 和 `PublicApiErrorV1_1` 的任意层级都必须被 strict Schema／敏感扫描拒绝：内部成本、批发价、最低利润、最大优惠、底价／floor、规则 ID／版本、知识证据 ID、供应商 ID／SKU／快照引用、内部审计码、模型内部分析、客户意图／价值等级、建议动作和内部销售阶段。服务端映射时只按逐字段白名单新建公共对象，禁止展开内部对象或先序列化后删字段。

### 4.8 客户可见文本来源与净化

报价对象中的 `label`、`notes`、`special_requirements`、`assumptions`、`exclusions`、`disclaimer` 及安全提示只允许来自：

1. 已确认的客户原始输入，经长度、Unicode、控制字符和展示转义校验；
2. 有 ID、版本和审核状态的公开目录或公开话术模板。

服务端内部保存每段公开文本的来源类型和来源 ID，但来源元数据不必发送给客户端。禁止从供应商快照、内部规则、内部计算账本、模型思维／内部分析、系统提示词或完整知识切片复制公开文本。

净化要求：

- 统一 Unicode 规范化，移除不可见控制字符和双向文本控制字符；
- JSON 中只保存纯文本，前端按文本渲染并执行 HTML 转义，禁止 `innerHTML`；
- 对模板设置字段级最大长度；客户文本沿用消息证据并截断到 Schema 上限；
- 投影前使用敏感值 canary、密钥模式、内部 ID 前缀和供应商专有词表扫描文本值；命中时停止投影并记录内部审计码，不把原值写入普通或错误日志；
- `assumptions`、`exclusions`、`disclaimer` 只能来自批准的公开模板，不允许模型自由生成。

## 6. 确定性计算规则

### 6.1 成本范围

```text
total_cost_fen =
  direct_cost_fen
  + procurement_wholesale_cost_fen
  + tax_cost_fen
  + delivery_cost_fen
  + installation_cost_fen
  + warranty_cost_fen
  + gift_cost_fen
  + free_service_cost_fen
```

其中 `direct_cost_fen` 包含当前方案适用的设计、材料、人工、施工和其他内部成本。所有成本均使用已激活规则或有效供应商快照，不接受模型生成金额。

### 6.2 最低成交金额

```text
floor_revenue_fen =
  ceil(total_cost_fen * 10000 / (10000 - minimum_margin_bps))
```

- `minimum_margin_bps` 范围为 `0..9999`；
- 中间乘法使用 `BigInt` 或等价的安全整数算法，避免超出 JavaScript 安全整数；
- 除法使用向上取整；最终结果必须仍在 `MoneyFen` 安全范围内；
- 若结果溢出、分母非法或规则缺失，停止报价。

### 6.3 最大现金优惠

```text
rule_discount_cap_fen = min(
  floor(subtotal_fen * maximum_discount_bps / 10000),
  promotion_rule.maximum_discount_fen（如存在）
)

margin_headroom_fen = max(0, subtotal_fen - floor_revenue_fen)

maximum_allowed_discount_fen = min(
  rule_discount_cap_fen,
  margin_headroom_fen
)
```

最终必须同时满足：

```text
approved_discount_fen <= maximum_allowed_discount_fen
final_revenue_fen = subtotal_fen - approved_discount_fen
final_revenue_fen >= floor_revenue_fen
final_revenue_fen >= total_cost_fen
```

赠品和免费服务不直接增加 `discount_total_fen`，但其内部成本先计入 `total_cost_fen`，因此会减少可用现金优惠空间。

### 6.4 代采差价

- 供应商批发价和客户成交价分别属于内部成本与客户收入，禁止把批发价直接复制到客户明细；
- 客户代采项目售价必须由激活的销售规则确定，并引用对应规则版本；
- 代采项目适用同一利润底线；不得以“赠送安装／配送”等方式漏记对应内部成本；
- `valid_until` 不得晚于所引用规则或供应商快照中最早的失效时间，但不向客户解释具体供应商失效原因。

## 7. 意向与促销策略

客户意向只决定**哪些已激活促销规则可以进入候选集**，不能绕过计算底线：

| 意向等级 | 默认候选策略 | 禁止行为 |
| --- | --- | --- |
| high | 正常报价、有限升级或公开套餐；只有客户明确议价或规则规定时才加入促销候选 | 因高意向抬高相同规则价格；模型自由加价 |
| medium | 正常报价，可加入规则允许的轻量赠品或服务 | 无证据自动贴标签；直接决定优惠金额 |
| low | 可加入激活的现金优惠、赠品或免费服务以降低决策门槛 | 突破成本／利润底线；无限叠加优惠 |
| unknown | 正常报价或先补问，不自动应用定向优惠 | 把未知当低意向；无依据促销 |

`value_level: low` 不等于客户主动要求优惠：若客户未提优惠，B 必须输出 `promotion.interest: "unknown"`。C 仍可依据独立的、已激活且允许低意向场景的促销规则提出候选权益，但不得把该权益描述为客户请求，也不得接受 B 提供金额。

意向等级相同时，规则选择必须可重复。候选规则排序固定为：

1. 过滤未激活、过期、地区／场景／金额不适用的规则；
2. 按 `priority` 升序；
3. 相同优先级按 `promotion_rule_id` 字典序；
4. 按 `exclusive_group`、`stackable_with_rule_ids` 和全局优惠上限校验；
5. 每应用一项非现金权益后重新计算内部成本和利润空间；
6. 任一步失败均不得保留部分写入。

## 8. 失败与安全输出

| 内部条件／审计原因 | 客户公开 reason | 客户安全提示原则 | 是否重试 |
| --- | --- | --- | --- |
| `supplier_quote_expired` | `quote_temporarily_unavailable` | 当前暂时无法生成可靠报价，请稍后重试 | 更新快照后可重试 |
| `promotion_not_applicable` | `adjustment_unavailable` | 当前调整无法应用，可查看其他方案 | 调整方案后可重试 |
| `margin_floor_exceeded` | `adjustment_unavailable` | 当前调整无法应用，可调整配置 | 降低优惠或调整配置后可重试 |
| `no_active_rule` | `quote_temporarily_unavailable` | 当前暂时无法生成可靠报价 | 规则修复后可重试 |
| `rule_conflict` | `quote_temporarily_unavailable` | 当前暂时无法生成可靠报价 | 规则复核后可重试 |

任何错误日志均不得记录完整请求头、API Key、完整供应商响应或客户未脱敏文本。

## 9. 事务与版本边界

- 供应商快照导入、规则导入、规则激活和报价保存分别定义事务边界；失败时完整回滚。
- 报价成功保存时，客户可见报价、内部计算账本、规则版本引用和供应商快照引用必须处于同一事务。
- 报价调整始终创建新的 `quote_id` 和递增的 `quote_version`，并保存 `parent_quote_id`。
- 已生成报价继续引用生成时的不可变快照；快照或规则失效不反向修改历史报价。
- 相同幂等请求必须返回同一报价版本，不得重复消耗促销或创建重复账本。

### 11.1 人工对账样例（虚构数据）

金额单位均为分：

```text
subtotal_fen = 1,100,000
total_cost_fen = 800,000
minimum_margin_bps = 2,000
maximum_discount_bps = 1,500

floor_revenue_fen
  = ceil(800,000 * 10,000 / 8,000)
  = 1,000,000

rule_discount_cap_fen
  = floor(1,100,000 * 1,500 / 10,000)
  = 165,000

margin_headroom_fen
  = 1,100,000 - 1,000,000
  = 100,000

maximum_allowed_discount_fen
  = min(165,000, 100,000)
  = 100,000
```

- 优惠 `100,000`：最终金额 `1,000,000`，恰好触及底线，允许；
- 优惠 `100,001`：最终金额 `999,999`，低于底线 1 分，拒绝；
- 若另赠送内部成本 `50,000` 的服务，则 `total_cost_fen = 850,000`，新底线为 `1,062,500`，现金优惠空间降至 `37,500`。
