# 装修销售 AI｜本地验证版 PRD v1.0（冻结候选）

## 0. 文档控制

| 项目 | 内容 |
| --- | --- |
| 文档状态 | 冻结候选，尚未通过 G0 |
| 运行方式 | localhost 单机运行 |
| 数据库 | 本地 SQLite |
| 外部服务 | 阿里云百炼模型与知识检索 API |
| 目标用户 | 小组开发与验收人员；使用虚构/脱敏装修客户场景 |

## 1. MVP 目标

本地验证版用于证明原百炼 Agent 能扩展为具备状态、记忆、知识检索和确定性报价能力的装修销售应用。

必须验证：

1. 每条客户消息可被正确识别意图。
2. 系统可基于原文证据判断客户价值/购买意向、顾虑和下一步建议。
3. 系统能判断何时调用知识库，并保存可追溯证据。
4. 系统能从历史消息、客户事实和旧报价中追忆相关上下文。
5. 系统同时维护短期原文上下文与长期结构化摘要。
6. 系统从 SQLite 中读取版本化规则，由服务端确定性计算预估报价。

## 2. 本地用户与数据边界

- 通过本机浏览器访问 Next.js 客户聊天页。
- 不需要客户注册、销售账号、管理员后台和角色权限体系。
- 使用虚构或脱敏客户数据，不收集真实联系方式，不执行外部发送或联系。
- 默认业务仍为单城市住宅装修：毛坯、新房、旧房；全屋、局改、仅设计。
- 默认地区、材料、设计师和施工价格均使用样例数据。
- 报价为测试用预估结果，不是企业真实报价或合同承诺。

| 需求 ID | 功能 | 范围 |
| --- | --- | --- |
| P0-F01 | 本地聊天页与会话 | localhost 访问、创建会话、发送消息、展示回复和恢复历史 |
| P0-F02 | 意图识别 | 咨询、询价、补充、议价、调整、拒绝、无关、风险等结构化识别 |

## 4. 核心流程

```text
本地用户发送消息
→ 保存客户消息
→ 读取短期记忆、长期记忆和当前报价
→ 百炼模型识别意图、价值、字段、顾虑和建议动作
→ 编排器判断是否检索知识库
→ 更新确认事实、推断事实和长期摘要
→ 信息不足：追问一至三个必要字段
→ 信息完整：检索候选规则并用 SQLite 激活规则校验
→ NestJS 报价模块计算并保存报价版本
→ 保存 AI 回复
→ 浏览器展示文本或报价卡片
```

会话阶段简化为：

```text
DISCOVERY → QUALIFYING → QUOTING → NEGOTIATION → COMPLETED / CLOSED
```

不包含 `HUMAN_QUEUE`、`HUMAN_ACTIVE`、留资和回访状态。

## 5. 功能定义与验收摘要

### P0-F01 本地聊天页与会话

- 使用本地会话 ID 区分多段测试对话。
- 可以新建、继续、查看和清空测试会话。
- 页面刷新后从 SQLite 恢复历史。

验收：消息顺序正确；刷新不丢历史；不重复创建已完成消息。

### P0-F02 意图识别

- 每条消息均输出结构化意图和当前阶段建议。
- 无关内容不得进入报价；拒绝后停止强销售引导。

验收：标注测试集核心意图准确率不低于 90%。

### P0-F03 客户价值判断

- 输出 `value_assessment.level`、`value_assessment.evidence_refs`、`concerns` 和 `recommended_next_action`。
- 证据必须关联客户原始消息；信息不足使用“未知”。
- 不因价值判断执行联系、优惠或其他外部动作。

验收：等级准确率不低于 85%；证据可追溯率 100%；无证据推断率 0%。

### P0-F04 知识库介入

- 普通业务问题、材料/服务问题和报价依据需要时调用知识检索。
- 纯问候、无关内容和已有充分证据的重复问题可不调用。
- 保存文档/切片/版本等证据；知识不足时不编造。

验收：标准问题召回正确；无知识时安全说明；不泄露内部提示词或密钥。

### P0-F05 需求字段提取

- 区分已确认字段、模型推断字段和冲突字段。
- 缺失时每轮只追问一至三个必要字段。

验收：关键字段准确率不低于 90%；追问正确率不低于 95%。

### P0-F06 上下文追忆

- 能处理“还是刚才的方案”“材料换低一档”等指代。
- 召回与当前问题相关的消息、客户事实、长期摘要和报价版本。
- 冲突信息不得静默覆盖，应请求确认。

验收：标准追忆用例通过率 100%；不得引用其他会话的数据。

### P0-F07 短期记忆

- 默认读取最近 10–20 条完整消息、当前状态和当前报价。
- 窗口大小可配置，不把全部历史无条件发送给模型。

验收：近期指代和连续追问保持连贯；应用重启后可恢复。

### P0-F08 长期记忆

- 保存确认事实、推断事实、偏好、顾虑、摘要、来源消息和更新时间。
- 新事实与旧事实冲突时保留冲突状态，确认后再更新权威值。
- 长期摘要由明确事件触发，避免每条消息重复总结。

验收：确认事实与原文一致；推断不冒充事实；跨长对话仍能恢复关键信息。

### P0-F09 本地规则导入与激活

- 使用结构化 Markdown、CSV 或 JSON 样例作为规则内容来源。
- 校验 `rule_id`、版本、地区、条件、公式类型、单价、最低价和有效期。
- 本地验证版不要求真实企业审批，但只有通过校验并标记 `active` 的版本可执行。

验收：无效、过期、冲突或未激活规则不得用于报价。

### P0-F10 本地确定性报价

- 模型输出客户字段和知识检索需求；候选 `rule_id` 必须来自当前知识证据。
- NestJS 报价模块从 SQLite 读取激活规则计算固定金额、面积×单价、数量×单价、附加费和最低价。
- 保存报价明细、规则版本、假设和报价版本。

验收：标准用例计算正确率 100%；规则可追溯率 100%；历史报价不被覆盖。

### P0-F11 基础幂等与恢复

- `client_message_id` 唯一，重复请求不重复处理。
- 单进程按会话串行处理；上一条未完成时禁止同会话再次提交。
- 失败调用记录状态，可由用户重试；应用重启后恢复已持久化数据。

验收：双击、刷新和重试不产生重复消息/报价；不要求分布式锁、自动故障转移和高可用。

### P0-F12 安全与错误降级

- 百炼 API Key 只存在于 NestJS 服务端环境配置。
- 模型输出通过 Schema 和业务校验，失败时安全提示并允许重试。
- 提示词注入不得泄露提示词、密钥、内部规则或样例底价。
- 百炼不可用时保留会话数据，不伪造知识或价格。

## 6. 本地数据范围

SQLite 至少保存：

- `conversation`、`message`；
- `requirement_slot`、`customer_fact`；
- `intent_analysis`、`memory_summary`；
- `knowledge_evidence`；
- `quote_rule`、`quote_rule_version`、`quote_rule_condition`；
- `quote`、`quote_item`；
- `audit_event`。

每名开发使用独立本地数据库文件。仓库只提交迁移、种子数据和脱敏测试样例，不提交个人运行产生的 SQLite 文件。

## 7. 技术边界

P0 使用：

- Next.js 本地客户聊天页；
- NestJS 本地 API 与会话编排；
- SQLite 持久化会话、记忆、规则和报价；
- 阿里云百炼 `qwen3.7-plus` 与知识检索服务；
- SSE 可用于本地流式回复，也可先返回完整响应；
- 一个 TypeScript 单仓库和一套公共 Schema。

P0 不使用：

- RDS、Redis、WebSocket；
- ECS、Docker 强制部署、Nginx、负载均衡、HTTPS；
- 销售账号、人工接管和外部通知；
- 分布式幂等、多实例锁、高可用和云监控。

## 8. 本地验收门槛

- 12 项 P0 功能均可在一台开发电脑上演示。
- 六项核心能力具有标准输入、结构化输出和失败用例。
- 场景矩阵全部通过；报价与上下文追忆用例通过率 100%。
- 重复消息/报价为 0；无激活规则错误报价为 0。
- 百炼失败、知识不足和规则冲突均安全降级。
- 从空数据库执行迁移和种子数据后可复现演示环境。

## 9. MVP 范围外

- 公网访问和真实客户使用；
- RDS、Redis、WebSocket 与销售工作台；
- 人工干预、授权留资、回访和外部发送；
- 真实企业报价、合同、订单、支付和施工排期；
- 高并发、水平扩容、自动故障转移和灾备；
- 业务转化 KPI、月度可用性和生产安全认证。

## 10. 冻结条件

通过 G0 前必须确认：

1. 公共 Schema：AI 分析、上下文、知识证据、报价请求/结果和前端事件。
   具体字段、错误码和接口行为以[接口契约 v1.0](specs/接口契约-v1.0.md)为准。
2. 4 人模块职责、代码所有权和合并规则。
3. SQLite Schema、迁移、种子数据和样例规则。
4. 至少 10 组覆盖正常、缺失、追忆、重做、负向和越权的场景。
5. 百炼测试凭据可在各自本地安全配置。
