# 装修销售 AI｜项目文档索引

## 项目 Brief

本项目当前 MVP 定义为 **localhost + SQLite 本地验证版**。目标是用 4 人并行开发验证：意图识别、客户价值判断、知识库介入、上下文追忆、短期与长期记忆，以及基于本地版本化规则的确定性预估报价。应用和业务数据运行在本机，模型与知识检索通过网络调用阿里云百炼；不以公网发布、真实客户留资、人工接管或高并发为本期验收目标。

## 本地 MVP 必须实现

1. **意图识别**：每条消息识别咨询、询价、补充、议价、调整、拒绝、风险等意图。
2. **客户价值判断**：输出高/中/低/未知意向、原文证据、顾虑与建议动作。
3. **知识库介入**：按需检索企业、材料、服务、地区及报价依据，不无条件调用。
4. **上下文追忆**：识别“刚才方案”“还是中档”等指代并恢复相关历史事实和报价。
5. **短期与长期记忆**：保存近期原文、确认事实、推断事实、偏好、顾虑和摘要。
6. **本地确定性报价**：从 SQLite 读取已激活规则，由 NestJS 报价模块计算并保存版本。

## 本期明确不做

- 公网部署、ECS、Nginx、HTTPS、负载均衡和云可用性。
- RDS、Redis、WebSocket、销售在线状态和多实例协调。
- 实时或异步人工接管、销售认领、回访任务和真实客户联系。
- 真实客户 PII、正式合同价、在线支付、订单和施工排期。
- 多租户、高并发、水平扩容和跨区域灾备。

## 当前 G0 阻塞项

1. 四人确认公共 TypeScript Schema、API 事件和模块接口。
2. 准备脱敏/虚构的默认城市、知识内容与报价规则样例。
3. 确认百炼测试 Workspace、API Key 和可用配额。
4. 确认 SQLite Schema、迁移、种子数据和每人独立数据库约定。
5. 确认场景矩阵、完成定义和分支/合并规则。

- 产品功能冲突时，以 PRD 为准。
- 知识与报价内容冲突时，以知识库规范和 SQLite 中已激活的规则版本为准。
